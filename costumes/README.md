`skirtunder_0..10.png`(다리 **뒤**: 앞에서 본 코트 자락 · 트인 치마의 뒷자락) · `skirtover_0..10.png`(다리 **앞**: 허리 장식 · 앞의 띠 · 뒤에서 본 치마),
다리와 같은 크기표이고 그 층이 없는 프레임은 1×1 빈 칸. 다리는 신발 칸이 정한다:
- 신발 아바타가 없거나 드레스와 같은 세트의 신발 → `hero/3/<번호 + 1000>` = 아랫층 + **그 세트의 다리** + 윗층(빌드가 합친다 — 그래서 층 치마 세트는 `leg_*` 가 있어야 한다).
- 다리를 가진 **다른** 세트의 신발 → `hero/3/<드레스 × 1000 + 신발>`(예: 210 드레스 + 208 신발 = `hero/3/210208`) = 아랫층 + **그 신발의 다리** + 윗층 —
  빌드가 조합마다 한 장씩 만든다(`costume_sheets.skirt_combo_members`, 지금 207 · 210 × 9 = 18 장), 호스트가 고른다(`avatar_state::skirt_over_shoes`).
- 앞뒤를 다 덮는 드레스(201 웨딩드레스 · 209 엘프 드레스)는 지금처럼 한 장(`skirt_*`) — 신발을 가린다. 한 세트에 `skirt_*` 와 층이 같이 있으면 도구가 거절한다.
- 지금 층 치마 = **207 진홍의 검사-코트**(앞 · 옆은 다리 뒤로 늘어진 자락, 뒤에서는 다리를 덮는다) · **210 백은의 사신-드레스**(앞 · 옆은 트인 치마 사이로 다리, 뒤에서는 덮는다).
  두 세트의 첫 판 한 장짜리 치마는 층 + 그 세트의 다리로 픽셀까지 같게 다시 나온다(층으로 바꾼 것은 그림이 아니라 짜임).
- 게임은 여섯 자리 번호도 그대로 싣는다(probe `--h2-avatar 700:body:210,arm:210,head:210,leg:210208` — 리로드 · 그림 정상).

세트를 얻으면 그 세트의 아이템을 전부 얻고(가방이 아니라 **아바타 옷장**으로), 칸마다 다른 세트의 아이템을 섞어 입을 수 있다
(이안의 머리 + 율리케의 웨딩드레스 …). 그림이 없는 칸은 그 세트에 아이템이 없다(예: 드레스 세트는 갑옷 하나만).

- **번호** = 폴더 이름 앞의 숫자, 200..999. 게임 경로(`/hero/1/200` · 무기 `/hero/6/2200` 처럼 앞에 종류)가 되므로 배포본 번호(0..20 · 100..102)와 겹치면 안 된다. 캐릭터의 저장 기록도 이 번호로 의상을 기억하므로 **한 번 쓴 번호는 바꾸지 않는다**.
- 파일이 **하나도 없는** 파트는 의상이 덮지 않는다(그 파트는 장착 장비 외형 그대로). 파일이 일부만 있으면 오류. 무기는 직업마다 따로다 — 로그 무기만 그리면 로그만 의상 무기를 든다.
- 무기·보조손은 **그 칸에 장비를 들고 있을 때만** 의상 모습이다(맨손·빈 보조손에는 그리지 않는다; 휘두르는 소리는 장착한 무기 것). 머리·몸통·팔·다리는 장착과 상관없이 의상.

### `costume.txt` (UTF-8, `키 = 값`, `#` 줄은 주석) — ★ A3c 형식 · ★ A4 직업별 이름

```
set                 = 빙해의 검사               세트 이름 (필수)
head                = 이안의 머리               투구 칸 아이템 이름 — head_*.png 가 있으면 필수, 없으면 쓰지 않는다
head.desc           = 바람에 헝클어진 은발.     그 설명 — 이름칸 둘째 줄 (없어도 된다)
armor               = 이안의 낡은 옷            갑옷 칸 (body_* · arm_*)
armor.desc          = 이안이 입던 여행복.
shoes               = 이안의 낡은 신발          신발 칸 (leg_*)
shoes.desc          = 먼 길을 걸어온 장화.
weapon.berserker    = 이안의 낡은 대검          무기 칸 — 직업마다 (weapon_<직업>_*)
weapon.knight       = 이안의 낡은 도검
weapon.rogue        = 이안의 낡은 단검
weapon.desc         = 이안이 쓰던 은빛 칼날.    설명은 세 직업 공통 (weapon.<직업>.desc 로 직업마다도 된다)
offhand.knight      = 이안의 낡은 방패          보조손 칸 (offhand_<직업>_*) — 버서커는 없다
offhand.knight.desc = 진홍 십자의 남색 방패.
offhand.rogue       = 이안의 보조 단검
offhand.rogue.desc  = 왼손에 쥐는 은빛 단검.
```

- **칸의 그림이 있으면 그 칸의 이름이 있어야 하고, 그림이 없으면 이름을 쓰면 안 된다** — 도구가 둘 다 거절한다. ★ A4: 직업마다 따진다 — 그 직업의 그림(`weapon_knight_*` …)이 있으면 그 직업의 이름(`weapon.knight`, 없으면 `weapon`)이 있어야 하고, 그림이 없는 직업의 키(`offhand.berserker` …)는 거절한다. A3 의 `name` · `bag` · `desc` 형식도 거절한다(바꾸는 법을 알려 준다).
- 폭 = 게임 글꼴 그대로 **1 + 한글 음절 9 + 영문·숫자·기호·공백 6** px, 모든 값 **≤ 114 px** — 이름칸에 **잘리지 않고** 들어가야 해서 도구가 막는다. 옷장 목록 행은 77 px 까지 보이고(한글 7 자 + 공백 2 = 76 px 인 이안의 이름들은 온전히) 더 긴 이름은 `..` 로 자른다 — 이름칸에는 온전히.
- 쓸 수 있는 글자 = 한글 음절(KS X 1001 의 2,350 자) · 영문 **대문자** · 숫자 · 기호 · 공백. ⛔ 게임 글꼴에 **소문자가 없다** — 쓰면 도구가 거절한다.
- jar 의 `hero/costume.txt` 한 줄 = 아이템 하나 `<번호>\t<칸>\t<세트>\t<이름>\t<설명>`(EUC-KR, 무압축) — ★ A4: 직업마다 이름이 다르면 직업마다 한 줄이고 여섯째 필드가 직업 번호(0 버서커 · 1 나이트 · 2 로그). 옷장은 캐릭터가 **얻은 순서**로 그 칸의 아이템만 보여 준다.

|---|---|
| 프레임 크기 | 인덱스마다 고정. 몸통 7×6 · 8×7 · **7×5** · 5×6 · 8×7 (0·1·3·4 는 1×1 빈 칸 허용) · ★ 망토 26×14 · 24×14 · 26×14 · 스카프 9×3 (5..8, 없으면 빈 칸) / 팔 4×6 · 5×7 · 4×7 · 6×8 · 6×8 · 10×7 · 4×5 · 6×10 · 4×6 · 8×5 · 11×5 / 다리 11×12 · 12×12 · 10×12 ×4 · 14×11 · 10×12 · 14×11 · 12×12 · 13×11 / ★ 머리 16×14 · 15×14 · 16×14 / 버서커 무기 10×23(또는 10×24) · 25×10 · 18×18 · 24×7 · 24×7 · 3×7 · 3×18 / 나이트 무기 9×14 · 9×14 · 14×9 · 14×9 · 3×16 / 로그 무기 9×14 · 9×14 · 14×9 · 14×9 · 1×1 / 나이트 방패 15×17 · 7×17 · 15×17 / 로그 둘째 단검 7×10 · 7×10 · 10×7 · 10×7(또는 11×7). 위치는 직업 애니메이션이 정하므로 크기를 바꾸면 조각이 어긋난다 |
| 투명 | 인덱스 PNG = 팔레트 0 번(tRNS 가 없어도 0 번이 투명) · RGBA = 알파 0 · 알파 없는 RGB = `#ffffff`. **반투명은 안 된다**(게임 시트는 투명/불투명 둘뿐). ⛔ **진짜 흰색(흰자 · 머리 빛 · 칼날 빛)은 팔레트 0 번이 아닌 다른 칸에 따로** — 0 번의 색도 `#ffffff` 라서, 흰색을 0 번으로 칠하면 그 점이 뚫려 뒤 배경이 비친다(배포본 시트도 `#ffffff` 칸이 둘이다). 2026-10-01 이안 머리의 눈·머리 빛과 무기 칼날 빛이 이렇게 뚫렸다(초안 생성기 버그 — 고침, 생성기가 이제 다시 읽어 검사한다) |
| 색 | 255 색까지. 16 색 이하면 시트가 4 비트로 작아진다. 배포본 색은 거의 전부 0x1f 간격 격자(`00 1f 3f 5f 7f 9f bf df ff`) — 벗어나도 되지만 도구가 알려 준다 |
| 좌우 반전 | 게임이 자동으로 만든다. 반전본을 따로 그리지 말고, **뒤집혀도 어색하지 않게** 그릴 것(다리 3·5 만 반전 없이 쓰인다) |
| 실루엣 | 바탕 프레임의 외곽을 그대로 두고 안을 칠하는 것이 가장 안전하다(이웃 조각과 이음새가 안 생긴다) |
| 저장 형식 | 아무 편집기·아무 압축으로 저장해도 된다. 게임은 **무압축** PNG 를 요구하지만(반전 사본을 PNG 바이트 안에서 만든다) 그 변환은 도구가 한다 |

`--h2-avatar 700:body:200,arm:200,leg:200,head:200,weapon:200,offhand:200`(상태 없이 바로).
⛔ **기기용 전역 시험 파일 `wie_avatar.txt` 는 2026-10-01 에 없앴다**(사용자: *"아바타는 이제 아바타옷장에서 입은거로만
적용되어야해"*) — 앱은 그 파일을 읽지 않는다. 기기에서 의상은 **옷장(아래 길)에서 입은 것만** 보인다.
게임 안의 길 = **메뉴 → EQUIPMENT → 오른쪽 열에서 RIGHT(또는 칸 탭) → 투구 · 갑옷 · 신발 · 무기 칸 → OK → 그 칸의 아바타 옷장 →
OK(착용 · 입은 것에 OK = 해제)** (★ A3c). 호스트는 **jar 에 실제로 있는 번호만** 입힌다 — 에셋을 재생성하지 않은 빌드에서는
그 아이템이 「착용불가」로 보일 뿐 죽지 않는다.

**기기의 옷장에 넣기 (시험용 지급 길, ★ A3c)**: 릴리스 빌드는 디버그가 안 되므로 adb 표시 파일로 —
`adb shell "echo 1 > /sdcard/Android/data/com.hero2remake.app/files/wie_costume_grant.txt"` 후 앱을 다시 켜면(숫자 = 세이브
슬롯, `1 3` 처럼 여럿) 에셋이 만드는 아이템 전부가 그 슬롯 캐릭터의 옷장에 **들어가기만** 한다(입히지 않는다 · 이미 가진
아이템은 또 주지 않는다 · 표시 파일은 먼저 지워진다 · 슬롯에 세이브가 없으면 아무것도 안 한다). ★ A5: **세트 번호(200~999)를 같이 쓰면
그 세트만** — `echo 1 2 3 4 5 202 203 204 > …` = 다섯 슬롯에 새 세트 셋만(보상 세트 200 · 201 은 빼고). ★ A4: 그 슬롯 세이브의 직업이
입을 수 있는 아이템만 — 버서커에게 보조손은 없다. 로그 = `avatar: costume grant: slot N (knight) …`.
실제 게임의 지급 길은 회차 클리어 보상(위)이고, probe 로는 `--h2-clear <f>` 가 같은 길을 연다.
